# Web UI デザイン再構築メモ (`internal/ui`)

## 0. 目的と前提

- **題材と主役**: `quota-fleet` の主役は「ジョブの状態と数値（ID・件数・残量・時刻）」である。
- **利用者と判断**: 一人の運用者（ゆうや）が画面を開いた瞬間に「何が動いているか／どこで詰まっているか／自分の判断が要るものはどれか」を一目で判断できることを最優先する。
- **制約**: API（`internal/ui` 以外のサーバー側コード）には一切手を入れず、全画面・全操作・配置を維持したまま、文字・地・線の関係を題材から組み直す。アセットは `internal/ui` への埋め込みのみで、外部リクエスト（CDN・Web フォント等）は発生させない。

## 1. 見本の観察記録

### 参照した一次資料
- 記事本文: Linear "A calmer interface for a product in motion" (`https://linear.app/now/behind-the-latest-design-refresh`, Charlie Aufmann / Maxime Heckel, 2026-03-12)
- 境界の比較図: 同記事内の新旧比較図 (`https://webassets.linear.app/images/ornj730p/production/67561baa677fbc429d94edd080e95aecabb6bae2-3904x2720.png?w=1600`) — 実際に取得・閲覧して確認済み。

### 主役・必要情報・操作がどこで結びつくか
- 一覧行の左端に小さな状態ドットと項目名（`Needs design`, `/changelog` 等）、右端に件数（`5`, `2` 等）が揃い、視線が横に一往復するだけで「対象と件数」が結ばれる。
- フィルタや表示切替（`Filter` / `Display` や `Labels` / `Priority` / `Projects` / `Teams` タブ）は一覧の直上にまとまり、内容を読む視線を遮らない位置関係にある。

### 制作者の説明（原文の要点）
- **Don't compete for attention you haven't earned**: 情報密度の高い画面では全要素に同じ視覚的重みを与えない。作業の中心（メイン領域）に焦点を残し、移動や補助を担うナビゲーション（サイドバーや上部タブ）の明るさを数段階下げて後退させた。アイコンの過密さや不要な色付き背景も削っている。
- **Structure should be felt not seen**: 境界線や区切り線が増殖して画面を騒がしくしていたため、線の数を減らしコントラストを弱め、角を柔らかくすることで、視界を散らかさずに構造を伝える方針を採った。
- **色味の調整**: 旧来の青みがかった冷たいグレーから、くすまない範囲でわずかに温かみのあるニュートラルなグレーへ寄せた。

### 自分が観察した形（比較図の左＝新版、右＝旧版）
- **右（旧版）**: 上部バー下、`Filter / Display` 上下、`My issues` 下、さらに矩形枠で囲まれたタブバーと、水平の区切り線が何段も重なり、一覧本体より先に枠線が視界に入る。
- **左（新版）**: 水平の区切り線が大幅に減り、上部操作は小さな丸ボタンへ収まり、タブは外枠の矩形を廃した穏やかなピル型になっている。一覧行の間には罫線がなく、左端の小さな色点・項目名・右端の等幅的な件数だけでまとまりが読める。背景も青みの強い黒ではなく落ち着いた暗灰になっている。

### 今回に使える条件と捨てる条件
- **使える条件**:
  - 繰り返し開く運用画面において、ヘッダー／ナビゲーションや区切り線といった脇役の輝度・主張を内容より下げる判断（特に方向A「計器盤」の設計指針として直接適用）。
  - 状態を「小さなランプ点＋短いテキスト」で表し、行や数値の整列と間隔でまとまりを読ませる構成。
  - ただし、入力欄の輪郭やキーボードフォーカス（`:focus-visible`）まで一律に薄くすると操作位置を見失うため、フォーカス輪郭と操作境界は十分なコントラストを維持する。
- **捨てる条件**:
  - Linear 固有の左サイドバー構造や独自フォントへの依存（今回は既存トップバー配置とシステムフォントスタックを維持）。
  - 「色点のみ」に頼る状態識別（白黒表示や Forced Colors Mode でも判別できるよう、点の形状差・記号・枠線種別を併用する）。

## 2. 二つの美的方向（`html[data-direction]`）

計器盤（`console`）と台帳（`ledger`）の二方向は両方残し、それぞれ**ダークモード（`console`）／ライトモード（`ledger`）**として運用する決定とした。

- **切替 UI**: ヘッダー右上の切替ボタンの表示名は「`ダーク`」「`ライト`」とし、方向名（計器盤／台帳）は `data-direction` 属性値（`console` / `ledger`）・ボタンの `aria-label`（`ダーク（計器盤）` / `ライト（台帳）`）・本設計メモに残す。
- **初期表示と永続化**: `localStorage` のキー `qf-direction` に保存済みの選択がある場合は常にそちらを優先する。保存済みの選択が無い初回訪問時は OS／ブラウザの `prefers-color-scheme` を参照し、`dark` なら `console`、`light` なら `ledger` を初期表示とする（判定できない場合は `console` にフォールバック）。選択値は再訪時および別タブ間（`storage` イベント）で復元・同期し、`meta[name="color-scheme"]` も選択方向に連動させる。

### 方向A: 計器盤 (`console`)

- **題材のどの面が文字・地・線に現れたか**:
  - **地**: 暗灰（`#111215`）を作業面、さらに一段暗い `#0c0d10` をトップバー（脇役）に割り当て、ナビゲーションが主役のジョブ一覧より前に出ない構成にした（Linear の観察判断を適用）。
  - **文字**: 状態別件数・ID・時刻・バージョン・チェーン進捗など照合対象の数値はすべて等幅（`--mono`）かつ `font-variant-numeric: tabular-nums` で桁を揃えた。セクション見出しは小ぶりな大文字トラッキングで控えめに添え、数値とタイトルを主役に据えた。
  - **線**: 状態別件数（`.stat-grid`）は個別の箱で囲わず、1px の静かなヘアラインで区切った連続計器帯として並べた。テーブルやカードの外枠も透過度の低い細線（`rgba(255,255,255,0.075)`）に抑え、面の明度差と余白でまとまりを読ませる。
  - **状態表示**: 小さなランプ状の点（`::before`）＋等幅ラベルで示す。色だけに頼らず、成功はひし形、失敗・枯渇は塗り四角、実行中・キューは塗り丸、待機・保持・ドリフトは中抜きリング、下書きは中抜き四角と形状を変え、白黒でも判別可能にした。
- **具体的に何が読みやすくなるか**:
  - 暗い画面の上で「異常（赤の四角ランプ）」「保持・ドリフト（琥珀の中抜きリング）」「実行中（丸ランプ）」が瞬時に浮かび上がり、長時間開いたまま監視・トリアージする場面で目が疲れにくい。
  - 数値・ID・時刻が縦に揃うため、実行中ジョブやチェーンの前後関係、エージェント版数の差分を素早く照合できる。
- **弱点**:
  - 明るい室内や直射光下では暗地のコントラストが落ちやすい。
  - 長文のプロンプトやエラー詳細・判定理由をじっくり通読する場面では、明地ほど文章の落ち着きが出にくい。

### 方向B: 台帳 (`ledger`)

- **題材のどの面が文字・地・線に現れたか**:
  - **地**: 温かみのある未晒し紙の地（`#f5f1e8`）と明るい紙面（`#fbf9f4`）、控えめな見出し紙面（`#efe9dc`）を組み合わせ、業務台帳・記録簿としての落ち着きを出した。
  - **文字**: ページ見出し・セクション見出し・テーブルヘッダー・屋号にシステム明朝スタック（`"Hiragino Mincho ProN", "Yu Mincho", YuMincho, "Noto Serif JP", serif`）を用い、本文はサンセリフ（`--sans`）、ID・時刻は等幅の表形式数字とした。見出しと記録本文の骨格差で階層が一目で分かれる。
  - **線**: 角丸を最小（`2px`〜`0`）に抑え、墨色の水平罫線（表頭の上下に太めの墨線、行間に細い墨線）で台帳の行リズムを作った。ナビゲーションやタブの現在地も塗り潰しピルではなく墨色の下線で示す。行間・セル上下余白を `console` より広めに確保し、1件ごとの記録を落ち着いて追えるようにした。
  - **状態表示**: 印／札（スタンプ・タグ）風の矩形ラベルで示す。枠線の種類と先頭記号を状態カテゴリごとに変えており（成功: 実線＋`✓`、失敗・枯渇: 太枠＋`×`、実行中・待機列: 左太帯＋`▸`、保持・待機・ドリフト: 破線＋`◇`、下書き: 点線＋`·`）、色が完全に抜けた白黒表示でも形と文字で読める。
- **具体的に何が読みやすくなるか**:
  - ゲート判定の理由文、ジョブ詳細のキー・バリュー群、納品サマリやログ断片など「記録を読み込んで判断する」画面で、紙面の余白と明朝見出しの区切りにより文章のまとまりが追いやすい。
  - 明所環境や印刷・スクリーンショット共有時でも可読性が高い。
- **弱点**:
  - 行の上下余白を広く取っているため、一画面に同時に収まるジョブ件数は `console` より少なくなる。
  - 夜間や暗い作業環境で長時間常駐させる用途では画面の輝度が強めに感じられる場合がある。

## 3. 技術的確認事項

- **外部リクエストなし**: CSS / HTML / JS に外部 URL は一切含まれず、CSP `default-src 'self'` と `TestUIShellAndAssetsFollowSecurityRules` を満たす。
- **幅と状態への適用**: 全画面（ダッシュボード、ジョブ一覧フラット／チェーン、ジョブ詳細・ミニツリー、新規登録、保持中、ゲート判定、納品、エージェント版数）および空表示・エラーバナー・認証ゲートに両方向のトークンが適用される。狭幅（`<= 720px`）ではナビの横スクロール・2列統計グリッド・フィルタ縦積みにより崩れを防ぐ。
- **アクセシビリティ**: `:focus-visible` の明確なフォーカス輪郭、白黒でも判別できる状態記号・形状、および `@media (forced-colors: active)` でのシステムカラー境界を維持している。
