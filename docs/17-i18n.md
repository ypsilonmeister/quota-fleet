# docs/17 — Web UI の国際化（日本語／英語）

- 状態: 実装（Issue #11）
- 前提: docs/07（UI）、docs/14（通知）、docs/15（PWA）

## 1. 目的と範囲

Web UI（`internal/ui`）を日本語（`ja`、原典）と英語（`en`）で表示できるようにする。依存ライブラリは追加しない。

範囲外:

- CLI の出力、API のエラーメッセージ、`docs/` の翻訳
- 日時表示のロケール連動（従来どおり `YYYY-MM-DD HH:MM:SS`、ブラウザのタイムゾーン）
- サーバーが生成する文字列の翻訳（§7）

## 2. 構成

| ファイル | 役割 |
|---|---|
| `assets/i18n.js` | ロケール辞書（`ja` / `en`）と実行時の小さなモジュール（`__qfI18n`） |
| `index.html` | 静的な文字列を `data-i18n` 属性で指定する。要素の中身は空にする |
| `assets/app.js`, `assets/notify.js` | 動的な文字列をキーで引く（`t()` / `L()`） |

`i18n.js` は単独では配信しない。サーバーが `/ui/assets/app.js` として、`i18n.js`・`app.js` の順に連結して返す（`embed.go` の `shellAssets`）。辞書だけが取得できず、ラベルが空で操作もできないページになることを避けるためである。連結した結果はシェルの版数の計算とキャッシュの対象なので、オフラインでも読める。

- 固定の文は `app.js` の取得後（`defer`）に入る。それまでラベルは空になる
- `app.js` の取得に失敗した場合、アプリは起動せず、固定のラベルも空のままになる（再読み込みが必要）
- `notify.js` は辞書より先に実行されるので、辞書は読み込み時ではなく文を使う時に引く

## 3. 言語の決定と保持

1. `localStorage` の `qf-locale` が `ja` か `en` なら、それを使う
2. なければ `navigator.language` が `ja`（`ja-JP` など）なら日本語、それ以外は英語

ヘッダーの「JA / EN」で切り替える。保存するのは利用者が選んだときだけで、自動判定の結果は保存しない。別のタブでの変更は `storage` イベントで反映する。`<html lang>` も合わせて更新する。`localStorage` が使えない場合も、そのページ内の切替は働く。

ブラウザのページがない環境（node の単体テスト）では原典の `ja` を使う。

## 4. 切替の仕組み

切替では画面を作り直さない。表示中の文字列だけをその場で書き換えるので、入力中のフォーム、エラー表示、スクロール位置が保たれ、API の再取得も起きない。

そのために、動的な文字列は「引いた結果」ではなく「引く関数」を DOM に渡す。

- `i18n.lazy(key, params)`（`app.js` では `L`）は、呼ぶたびに現在の言語で文を返す関数
- `i18n.setText(node, value)` / `i18n.setAttr(node, name, value)` は、`value` が関数ならノードに記録して表示する。文字列なら記録を消して表示する
- `i18n.setLocale()` は文書全体をたどり、`data-i18n*` を引き直してから、記録した関数を呼び直す（同じノードでは関数が優先）

記録はノード自体が持つため、画面から消えた要素の記録は残らない。

## 5. 文字列の抽出方針

利用者が目にする文字列（画面の文言、`placeholder`・`title`・`aria-label`、確認ダイアログ、通知のタイトルと本文）は辞書に置く。

辞書に入れず、コードに直接書くもの:

- 全言語で同じ表記になる識別子や固有名: `quota-fleet`、`Agent`、`Host`、`Held ID`、`agent / host`、`target_ref`、バッジの `OK` / `DRIFT`、`pinned:` など
- API の値そのもの: 状態（`queued` など）、判定、イベント種別、プール名
- サーバーやブラウザが返した文（`error`、`reason`、例外の `message` など）

チェーンの進捗要約の状態名（日本語では「実行中」「失敗」）は表示名なので、辞書の `status.*` に置く。

`index.html` の `<noscript>` は JavaScript がないと翻訳できないため、英語のみにしている。`aria-label="Main navigation"` は従来から英語のみで、そのままにしている。

### 辞書の書き方

- キーは `領域.名前`（例: `jobs.loadMore`）。領域は画面や機能の単位
- 1行に1件、`"キー": "文",` の形で書く（テストがこの形を読む）
- 差し込みは `{名前}`。語順は言語ごとに変えられる。文を `+` で組み立てず、文全体を1件にする
- 区切り文字（「・」「、」）や前後の空白も言語で違うので、辞書に含める
- 英語は複数形の変化を避け、`label: n` の形にする（例: `Child jobs (2)`）
- 辞書にないキーは日本語に、日本語にもなければキー名のまま表示する

## 6. `data-i18n` と `t()` の使い分け

| 場所 | 書き方 |
|---|---|
| `index.html` の固定の文 | `<button data-i18n="header.refresh"></button>`（中身は空。子要素を持つ要素には付けない） |
| `index.html` の属性 | `data-i18n-placeholder` / `data-i18n-title` / `data-i18n-aria-label`（他の属性を足すときは `I18N_ATTRIBUTES` に追加する） |
| `app.js` で画面に置く文 | `el("h1", { text: L("jobs.title") })`。属性や子要素にも `L()` を渡せる |
| 複数の部品から組み立てる文 | `text: function () { return t("detail.heading", { id: id, title: title \|\| t("common.untitled") }); }` |
| 後から書き換える文 | `i18n.setText(button, L("common.loading"))`。`textContent` や `title` に直接代入しない |
| その場で使い切る文（`confirm`、通知のタイトルと本文） | `t(...)` |

`t()` の結果をそのまま DOM に置くと、表示はされるが言語を切り替えても変わらない。`L()` が返すのは関数なので、`+` で連結しない。

通知は表示した時点の言語になる（表示済みの通知は書き換えない）。

## 7. サーバーが生成する文字列

- 版数マトリクスの `limitation_note` は固定の日本語なので、UI は自分の辞書の文（`agents.limitationNote`）を表示する。日本語の文がサーバーの定数と一致することをテストで固定する
- 版数の変化イベントの詳細には、サーバーが日本語で生成する部分がある（例:「自動更新不可・手作業が必要」）。保存済みのデータなので UI では翻訳せず、英語表示でもそのまま出る
- API のエラー文などは届いたまま表示する

## 8. 新しい文字列の追加手順

1. `i18n.js` の `ja` と `en` の**両方**に、同じキーと同じ `{名前}` を追加する
2. §6 の方法で参照する。キーは `"jobs.loadMore"` のように**文字列リテラル全体**で書く（`"jobs." + name` のように組み立てない）
3. `go test ./internal/ui/` を実行する

言語を追加する場合は、`MESSAGES` と `LOCALES`、`detectLocale`、ヘッダーのボタン、テストの言語一覧を更新する。

## 9. テスト

`internal/ui/i18n_test.go`:

- `ja` と `en` のキー集合の完全一致、空の文がないこと、差し込み名の一致、重複キーがないこと
- `internal/ui` の HTML・JS・CSS・manifest などに、辞書ファイル以外で日本語の文字（かな、漢字、全角記号）がないこと。コメントも対象
- 参照するキーが辞書にあること、辞書のキーがすべて使われていること、`data-i18n` の要素が空であること
- `app.js` の切替ボタンと `storage` イベントの配線、よくある形の即時評価（`text: t(...)` や `textContent` への直接代入）がないこと
- 言語の判定と保持、差し込み、その場の書き換え（node）
- 英語表示の組み立て文、通知の文言、トグルの状態表示（node）
- `limitation_note` の日本語がサーバーと一致すること

node がない環境では node を使うテストは skip する。キー一致と日本語の走査は node なしで動く。

テストで分からないもの: 英語を直接書いた文字列、`\uXXXX` の形で書いた日本語、変数を経由するなど上の形に当たらない即時評価。レビューで確認する。`app.js` の画面描画そのものは自動テストで実行していないため、画面を足したときはブラウザで切り替えて確認する。
