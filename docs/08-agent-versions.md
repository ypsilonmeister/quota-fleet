# docs/08 設計: エージェント版数の棚卸しとドリフト通知（通知のみ）

状態: v1（2026-11-24、ゆうや決定「通知のみ先行」）
関連: docs/06（実装設計）、docs/07（UI/MCP）

## 0. 目的と原則

- 全ホストのエージェント（agy／Claude Code／Codex）の版数を fleet が把握し、**版のばらつき（ドリフト）と変化を検出して通知**できるようにする。
- 本フェーズは**通知のみ**。自動更新はしない（更新実行は次フェーズ。ピン留めや sudo 前提など、無人更新できない事情が実在するため）。
- §0 の原則（docs/07）は引き続き有効: 単一バイナリ、最小設定、黙った無効化をしない。

## 1. 検出（プローブ）

- 対象は fleet.yaml に登録されたホスト × そのホストで解決できるエージェント。
- 実行経路は既存の FileAccess（RunCommand）を再利用する。新規の接続経路は作らない。
- コマンドは `<agent の command> --version` を既定とし、エージェントごとに `version_args` で上書き可能にする（例: agy は `--version`）。
- 結果は次のいずれかで記録する: `ok`（版が取れた）／`not_found`（コマンドが無い）／`error`（実行失敗、理由つき）。失敗を版「0」などに化けさせない。
- トリガ: CLI `quota-fleet agents check` と API `POST /agents/check`（手動）。あわせて serve の定期実行（設定 `agents_check_interval`、既定 6h、0 で無効。無効化した場合は起動バナーに明示する）。

## 2. 保存

- `agent_versions`: ホスト×エージェントの最新状態（version_raw、比較用に正規化した version、status、checked_at）。
- `agent_version_events`: 変化の履歴。種別は `version_changed`（old→new）／`drift_started`／`drift_resolved`／`probe_failed`（初回失敗と回復も含む）。
- イベントは通知の正本であり、既読管理はしない（取得側が since で絞る）。

## 3. ドリフト判定

- 同一エージェントで、`ok` なホスト間の正規化版が2種類以上あればドリフト。
- 「遅れ」は最大版との比較で判定する（外部の最新版情報は引かない。**全ホストが一斉に古い場合は検出できない**という限界を明記し、将来の known-latest 設定で補う余地を残す）。
- 版の比較は semver として解釈できる場合のみ順序付けし、解釈できない版は「比較不能」として順序を断定しない。
- **ピン留め**: ホスト×エージェントに `pin: <version>` を設定できる。ピン中の対象は「遅れ」通知から除外し、表示では pinned と明示する（例: home-win の Codex 0.169.0 は上流ビルド事情による意図的なピン）。
- **要手作業の区別**: `manual_update: true` を設定できる対象（例: sudo が要る導入形態）は、遅れ検出時に「自動更新不可・手作業が必要」と分かる形で通知に含める。実際の更新は本フェーズの範囲外。

## 4. 表面（サーフェス）

- CLI: `quota-fleet agents` でホスト×エージェントの版マトリクスとドリフトを表示する。
- API: `GET /agents`（最新状態＋ドリフト要約）、`GET /agents/events`（`since` クエリ対応）、`POST /agents/check`（即時プローブ）。
- UI: 一覧画面群に「エージェント版数」の画面を1つ追加する（docs/07 の CSR 原則に従う。ドリフト中のエージェントを目立つ形に）。
- 通知: 変化イベントは既存 Notifier（webhook）にも流せるようにする。運用上の主経路は、コーディネーターが `GET /agents/events` を定期取得してチャットで知らせる形とする（導入手順は運用メモ側）。

## 5. 非目標

- エージェントの自動更新・ロールバック。
- 外部リリース情報（公式サイト等）との照合。
- fleet 未登録ホストの監視（登録は fleet.yaml への追記のみで済む。例: penguin は鍵配布済みで、ホスト登録は設定変更のみ）。

## 6. 受け入れ条件（本フェーズの完了）

1. shadow の全ホスト（ubuntu／ubuntu-vm／home-win）で3エージェント分の版が取得でき、マトリクスが CLI と API と UI で一致すること。
2. 版を人為的にずらしたホストでドリフトが検出され、`drift_started` イベントが残ること。戻せば `drift_resolved` が残ること。
3. ピン設定した対象が「遅れ」通知から外れ、表示で pinned と分かること。
4. プローブ失敗（コマンド不在・接続失敗）が `not_found`／`error` として区別され、黙って成功扱いにならないこと。
5. `CGO_ENABLED=0 go test ./...` が全 PASS。
